# Repository guidance

## Commands
- Use pnpm; `pnpm-lock.yaml` is the lockfile. `pnpm-workspace.yaml` only configures dependency build permissions, not multiple packages. Preserve its `allowBuilds` entries, including native `better-sqlite3`.
- `pnpm dev` starts both Vite and Hono with concurrently. Use `pnpm dev:web` for Vite alone and `pnpm dev:api` for `tsx watch server/index.ts`. The API listens on port 3000.
- Verify with `pnpm lint` and `pnpm build`; build runs `tsc -b` before Vite. For typechecking alone use `pnpm exec tsc -b`; for focused linting use `pnpm exec eslint src/path/to/file.tsx`.
- No test runner or test script is configured.
- Backend typecheck: `pnpm check:api`, using `tsconfig.server.json`. `pnpm build:api` emits Node ESM files in `server-dist/`; use `.js` extensions for relative backend imports so the compiled files run under Node. `pnpm build:all` builds frontend and backend; `NODE_ENV=production pnpm start` runs both from one Node process.
- Docker: `docker compose up -d --build` starts one app container on port 3000 behind the user's existing Nginx proxy. Do not add another proxy service. Compose defaults to binding `127.0.0.1`; `APP_BIND_ADDRESS` and `APP_PORT` configure the published endpoint. The package manager is pinned to pnpm 12.11.2. Both image stages use `node:24-alpine`; install build tools with `apk` and keep runtime `libstdc++` for native dependencies. Keep build/runtime libc environments consistent, and verify `better-sqlite3` when changing the base image.
- Known full-project lint failures: `src/components/ui/sidebar.tsx` violates `react-refresh/only-export-components`; `src/hooks/use-mobile.ts` violates `react-hooks/set-state-in-effect`. Run focused lint on changed files and report these separately when still present.

## Chat architecture and contracts
- `src/main.tsx` mounts `src/App.tsx` under `StrictMode`. App owns draft/provider/messages, loading/error state, and the active AbortController. Chat UI lives in `src/components/chat/`; editable shadcn components live in `src/components/ui/`.
- Flow: MessageComposer → App → `src/lib/chat-api.ts` → `server/app.ts` → `server/services/ai.ts`. The server entrypoint loads `dotenv/config` before importing the app and starts the Node adapter. Keep SDK imports and credentials on the server.
- `GET /api/health` returns plain text `ok`. `POST /api/chat` accepts JSON with `{ prompt: string, provider: string, stream?: boolean, googleSearch?: boolean }`. The Zod schema in `server/app.ts` trims prompt and requires non-empty text, restricts provider to `ChatGPT`, `Gemini`, or `Claude`, and validates optional flags as booleans. Google Search can only be enabled for Gemini. Use `c.req.valid("json")` after `@hono/zod-validator`; requests need a JSON Content-Type. Preserve `{ error: string }` responses for both schema failures and malformed JSON (handled by `app.onError`).
- Gemini is the only real provider. It uses `gemini-3.5-flash` with a 30-second SDK request timeout and on-demand client creation. ChatGPT and Claude return demo JSON replies; the initial UI provider is ChatGPT.
- Gemini with `stream: true` returns `application/x-ndjson`. Events are `{ type: "delta", text: string }`, optional `{ type: "grounding", grounding: GroundingData }`, `{ type: "done" }`, or `{ type: "error", error: string }`. Delta text is incremental; successful streams end with done, failures with error. Grounding metadata arrives before done and can originate from an SDK chunk with no text. Preserve UTF-8 decoding and buffering across arbitrary network chunks.
- Google Search is opt-in through `config.tools: [{ googleSearch: {} }]`; do not enable it for normal requests or silently fall back on errors. Grounded JSON replies include optional `grounding: { sources: { uri: string, title: string }[], searchEntryPoint?: string }`. Deduplicate sources, allow only HTTP/HTTPS URLs, and preserve Google's Search Suggestions HTML. `GroundingSources.tsx` renders suggestions in a sandboxed iframe without scripts or same-origin access, separately from model Markdown. Search availability and billing depend on the Google project/model.
- Non-streaming success and demo replies use `{ text: string }`. Errors before a stream starts use `{ error: string }`: 400 for invalid input, 503 for missing key, and for non-streaming provider failures 429 for quota/rate limits or 502 otherwise. Once streaming starts, provider failures are error events under HTTP 200. Do not expose raw SDK error messages to the browser.
- The browser requests streaming and supports JSON fallback. Update one assistant message per request using a stable ID. Stop preserves partial replies; New chat clears messages. Abort old requests and guard callbacks/finally blocks so they cannot mutate a newer chat or request. Propagate disconnects to the SDK AbortSignal and remove request listeners after completion.
- Conversation history is not sent; messages are memory-only. User messages render as plain text. Assistant replies use the lazy-loaded `MarkdownMessage` component with react-markdown, remark-gfm, and rehype-highlight; raw HTML is skipped. Markdown elements use Tailwind utilities in `MarkdownMessage.tsx`; generated syntax-token classes are styled in `src/components/chat/syntax.css`. SQLite is installed but unused.
- For route checks, import the app from `server/app.ts` and use `app.request()` without starting a listener. Live Gemini checks require a configured key and may incur usage; mocked checks can exercise empty output, quota errors, stream framing, truncation, and cancellation.

## Current boundaries and configuration traps
- `vite.config.ts` uses React and Tailwind plugins, aliases `@` to `src/`, and proxies `/api` to `http://localhost:3000` during development. `pnpm build` outputs only frontend assets; `pnpm preview` has no API proxy. With `NODE_ENV=production`, Hono serves `dist/` and the API on one origin. Register API routes before static serving; unknown `/api` routes and missing `/assets/` files must return 404 rather than SPA HTML. Resolve the static root relative to `import.meta.url`, not the current working directory. The existing reverse proxy must preserve streaming.
- `GEMINI_API_KEY` comes from the root `.env` or backend environment; never prefix it with `VITE_` or put credentials in browser code, logs, or docs. Restart the API after environment changes. `.gitignore` excludes `.env` and `.env.*`, except for a sanitized `.env.example`; never commit real credentials in any file. Ignore rules do not untrack already committed files or remove them from history.
- `tsconfig.app.json` includes all of `src` with browser/Vite types. `tsconfig.node.json` covers only `vite.config.ts`, despite its name. `tsconfig.server.json` covers `server/` separately; frontend `pnpm build` does not include it. `server-dist/` is generated and excluded from Git, ESLint, and Docker build inputs.
- `.dockerignore` excludes all `.env` files, local dependencies, and build artifacts. Inject `GEMINI_API_KEY` into the backend container at runtime; never use build arguments or image layers for credentials. The runtime is non-root and read-only with writable `/tmp`; SQLite remains unused, so no data volume is needed yet. Server SIGTERM/SIGINT handlers allow in-flight requests to finish before shutdown.
- ESLint currently applies browser globals and React rules to every TS/TSX file, including `server/`; account for this when updating server lint configuration.
- TypeScript uses `verbatimModuleSyntax` and `erasableSyntaxOnly`: use type-only imports where appropriate and avoid enums or parameter properties. Unused locals and parameters fail typechecking.
- Tailwind v4 is imported from `src/index.css`; use utility classes in chat components for layout, controls, responsive behavior, and Markdown formatting. There is no `App.css`. Extend the existing `@theme inline` tokens for reusable app colors (`text-strong`, `bg-accent-soft`, `border-accent-border`, `bg-code`) instead of adding page-level CSS selectors. `syntax.css` is limited to token classes generated by the highlighting plugin. shadcn uses Radix Nova and Lucide icons. Theme tokens and `dark:` utilities follow the system `prefers-color-scheme` setting.
